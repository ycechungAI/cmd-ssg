# v1.1.0 — Correct rendering & safer output

**Type:** minor · **Status:** planned · **Depends on:** v1.0.4

## Goal

Generated sites render correctly: whole-document Markdown, clean text paragraphs, and working stylesheets and links at any depth. The tool also never deletes a folder it didn't create.

## Scope

Bugs B7, B13, B14, B15 and B16; new flags `--clean`, `--lang`, `-q/--quiet`; a better index page; template cleanup; a tooling upgrade.

## Changes

### Safe cleaning (B7)

- Remove the implicit wipe of `./dist`.
- New flag `--clean`. Before writing, delete the output directory's contents, but **only** if `<out>/.cmd-ssg` exists. Otherwise fail with `Refusing to clean <out>: not created by cmd-ssg (missing .cmd-ssg marker)` and exit 2.
- Every build writes `<out>/.cmd-ssg` containing `{ "version": "<pkg version>", "generatedAt": "<ISO date>" }`.
- Without `--clean`, files are overwritten in place. Stale pages may remain; mention this in the README.

### Stylesheets & assets (B13)

- `-s` value classification:
  - `http://` or `https://` URL: used as-is on every page.
  - Local path: must exist (else exit 2). Copied to `<out>/assets/<basename>`.
- Each page gets a **relative** href: `path.posix.relative(pageDir, "assets/<basename>")`, e.g. `../assets/new.css` for a page one level deep.
- `.css` files found inside the input tree are copied to the same relative path under `<out>` (not turned into pages), so authors can reference them.
- The href still passes through `sanitizeUrl` + `escapeHtml`.

### Link encoding (B14)

- Index hrefs: `relOut.split("/").map(encodeURIComponent).join("/")`.
- Output filenames still replace spaces with `_`. No other renaming.

### Markdown (B15)

- `renderPage` passes the **whole file** to `md.render()`. The `filter(line => line)` line splitting and the `<p>` wrapper in `lib/parser/markdown.js` are deleted.
- markdown-it options: `{ html: false, linkify: true, typographer: false }`. `html: false` must stay; it's the XSS boundary. Add a comment saying so.
- Title: text of the first level-1 heading token (`heading_open` with `tag === "h1"`). Otherwise the filename without its extension.
- If the document already starts with that H1, the template does **not** emit its own `<h1>`, to avoid a duplicate heading. The template gets `options.emitHeading` (boolean).

### Plain text (B16)

- New `parseText(str)`:
  1. Normalize `\r\n` to `\n`.
  2. Title rule is unchanged: line 1 is non-empty and lines 2–3 are blank.
  3. Split the rest on `/\n\s*\n/`, trim each block, drop empty blocks, and join the internal newlines with a single space.
- Remove the `"_space_"` sentinel.

### New flags

- `--lang <code>`: sets `<html lang>`. Default `en`. Validate against `/^[a-zA-Z]{2,3}(-[a-zA-Z0-9]{2,8})*$/`, else exit 2.
- `-q, --quiet`: suppress the per-file "File created ->" lines. Errors and warnings still go to stderr.
- Config file supports `lang` and `clean`.

### Index page

- Entries are sorted by relative path and labelled with the page **title** (escaped), falling back to the filename.
- Pages in subfolders are grouped under the folder name as nested `<ul>`.
- The `<title>` and `<h1>` stay "Home" until `siteTitle` arrives in v2.0.0.

### Template cleanup (`generateHtmlTemplate.js`)

- The output starts with `<!doctype html>` at byte 0, with no leading newline or indentation.
- Remove `<meta http-equiv="X-UA-Compatible">`.
- Use 2-space indentation consistently.

### Tooling

- ESLint 9 flat config (`eslint.config.js`) with `@eslint/js` recommended + `globals.node` + `globals.jest`. Delete `.eslintrc.json`.
- Prettier 3, Husky 9 (`"prepare": "husky"`), lint-staged 15.
- CI matrix `os: [ubuntu-latest, windows-latest]` × `node: [18, 20, 22]`. Add an `npm run prettier-check` step.
- `jest --coverage` with `coverageThreshold.global = { lines: 80, branches: 70 }`.

## Behavior & acceptance criteria

| Scenario | Expected |
|---|---|
| Build into an existing `dist` with no marker, no `--clean` | Files written alongside; nothing deleted |
| `--clean` on a dir with no `.cmd-ssg` | Refused, exit 2, dir untouched |
| `--clean` on a previous output dir | Contents replaced |
| `-s sample_css/new.css`, page at `a/b/x.html` | `<link href="../../assets/new.css">`, file exists |
| `-s https://cdn/x.css` | Same absolute href on all pages, nothing copied |
| Markdown with a fenced code block, multi-line list, table | Rendered as single `<pre><code>`, `<ul>`, `<table>` |
| Markdown starting with `# Hello` | `<title>Hello</title>`, exactly one `<h1>` |
| Markdown containing `<script>` | Escaped (html disabled) |
| Text containing the literal `_space_` | Preserved verbatim |
| Text with 4 consecutive blank lines | No empty `<p>` |
| File named `C# notes?.md` | Index href is `C%23_notes%3F.html`, and the link resolves |
| `--lang fr` | `<html lang="fr">` |
| `--lang '"><x'` | Rejected, exit 2 |

## Tests

- Golden-file tests: `test/fixtures/{md,txt}/*` → `test/fixtures/expected/*.html`, with whitespace-normalized comparison. Cover fences, nested lists, tables, links, title detection, and the duplicate-H1 rule.
- e2e tests for `--clean` (marker present and absent), stylesheet copying at depth 0/1/2, a remote stylesheet, `--lang` validation and `--quiet`.
- Windows CI runs the full suite, which validates path separators.

## Out of scope

- Front matter, layouts, config schema, allowlist URL sanitizer — v2.0.0.
- Asset passthrough for images — v2.0.0.

## Migration notes

- **Behavior change:** the default `dist` is no longer wiped. Use `--clean`; the first `--clean` on an old `dist` without a marker is refused, so delete it manually once.
- Markdown output changes (correct block structure, real titles). Users who styled `p > h1` must update their CSS.
- Stylesheet hrefs become relative to an `assets/` copy.
