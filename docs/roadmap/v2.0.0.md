# v2.0.0 — Architecture & config

**Type:** major (breaking) · **Status:** planned · **Depends on:** v1.1.0

## Goal

Separate a pure, reusable core library from the CLI, give the configuration a validated contract, and add the authoring features (front matter, layouts, assets) that make cmd-ssg usable for real sites.

## Scope

Module restructure, the `ssg.config.json` schema, front matter, a URL allowlist, layout templates, asset passthrough, and the Node and module-system baseline.

## Changes

### Module layout

```
src/
  core/
    discover.js   // walk input tree → [{ abs, rel, kind: "page"|"asset" }]  (no symlinks)
    parse.js      // parseText(), parseMarkdown() → { title, html, meta }
    render.js     // renderPage(), renderIndex(), escapeHtml(), sanitizeUrl()
    write.js      // writeSite(plan, out, { clean }) — the only fs-writing module
    build.js      // build(config) → { pages, assets, warnings }  (orchestrates)
  cli/
    index.js      // commander, config loading, printing, exit codes
index.js          // package "main": re-exports core API, no side effects on require
```

- `bin/index.js` becomes a one-line shim to `src/cli/index.js`. `bin/helper.js`, `bin/outputCheck.js`, `generateHtmlTemplate.js` and `lib/parser/` are removed after their logic moves.
- Public API (documented in the README): `build(config)`, `renderMarkdown(str)`, `renderText(str)`.
- **Module system:** decided by an ADR at `docs/adr/0001-module-system.md`. Recommendation: **ESM** (`"type": "module"`), since chalk 5 and most current deps are ESM-only. If ESM is chosen, `require()` consumers need dynamic `import()`, which is part of what makes this a major release.

### Config contract

- The file is `ssg.config.json`. It's auto-discovered in the CWD, and `-c` still overrides the path.
- Schema (validated with a small hand-written validator, so no new dependency):
  ```json
  {
    "input": "string (required)",
    "output": "string, default \"dist\"",
    "stylesheet": "string | string[]",
    "lang": "string, default \"en\"",
    "siteTitle": "string, default \"Home\"",
    "layout": "string (path to layout.html)",
    "clean": "boolean, default false",
    "drafts": "boolean, default false"
  }
  ```
- Unknown keys and wrong types are **errors** that name the key and the expected type. This is breaking: the old `future-implementation` key now fails.
- Precedence: CLI flags, then the config file, then defaults.

### Front matter (Markdown and text)

- A leading `---\n…\n---` block of `key: value` lines. This is a deliberately minimal YAML subset (strings, booleans, ISO dates), so no YAML dependency.
- Supported keys: `title` (overrides the H1 and the txt title rule), `date`, `draft`, `description` (written to `<meta name="description">`, escaped).
- `draft: true` pages are skipped unless `--drafts`.

### Allowlist URL sanitizer

- `sanitizeUrl` accepts only relative URLs (no scheme), `#fragment`, `http:`, `https:` and `mailto:`. Anything else becomes `about:blank`.
- The existing recursive decoding (percent, HTML entities, control-character stripping) stays as defense in depth before the scheme check.
- All existing `xss.test.js` and `security.test.js` cases must still pass. Add cases for `file:`, `blob:`, `ftp:` and unknown schemes being blocked, and for `mailto:` and `/rel/path` being allowed.

### Layout templates

- `layout` points to an HTML file containing the slots `{{title}}`, `{{lang}}`, `{{stylesheets}}`, `{{content}}`, `{{siteTitle}}` and `{{description}}`.
- `{{content}}` and `{{stylesheets}}` are inserted as generated (already safe) HTML. All other slots are HTML-escaped. Unknown `{{…}}` tokens are left as-is and produce a warning.
- The built-in layout is equivalent to the v1.1.0 template.
- The index page uses the same layout.

### Asset passthrough

- Non-page files in the input tree with extensions in an allowlist (`.css .png .jpg .jpeg .gif .svg .webp .ico .pdf`) are copied to the same relative path. Everything else is ignored, with a summary warning count.
- Symlinks are still never followed (keep the `lstat` checks from `getAllFiles`).

### Baseline

- `engines.node` → `">=20"`. Drop Node 18 from CI.
- `-v` is replaced by commander's default `-V`. `--version` is unchanged.

## Behavior & acceptance criteria

- `require`/`import` of the package prints nothing and touches no files.
- `build({ input, output })` called programmatically produces output byte-identical to the CLI.
- A config with an unknown key fails with exit 2, and the message names the key.
- `draft: true` pages are absent by default and present with `--drafts`.
- A front matter `title` overrides the H1.
- With a custom layout, all slots are filled, and a `<script>` in `siteTitle` comes out escaped.
- `sanitizeUrl` allowlist cases pass, and every historical bypass test still passes.
- Images referenced from Markdown via relative paths resolve in the output.

## Tests

- Unit tests per core module, with pure functions and no fs except `write.js`.
- A programmatic API test calls `build()` against a temp dir.
- A config-validation table test covers each key with a valid value, the wrong type, and an unknown key.
- Layout slot escaping tests.
- e2e: the v1.x CLI e2e suite is ported and should still pass, except for the documented breaking changes.

## Out of scope

- Dev server, watch mode, incremental builds, sitemap/RSS, plugins — see [future.md](future.md).

## Migration notes

| From                                  | To                                                             |
| ------------------------------------- | -------------------------------------------------------------- |
| `config.json` passed with `-c`        | Same works. Rename to `ssg.config.json` for auto-discovery     |
| Extra keys in config                  | Remove them (now an error)                                     |
| `ssg -v`                              | `ssg -V` or `ssg --version`                                    |
| `require("@ycechung/cmd-ssg")`        | `import { build } from "@ycechung/cmd-ssg"` (if ESM is chosen) |
| Node 18                               | Node ≥ 20                                                      |
| `data:`/other-scheme stylesheet hrefs | Now blocked. Use `http(s)` or relative paths                   |
